## 1. Independent audit of the controller firmware

### 1.2 Startup calls the switch sampler with the wrong ABI
Confidence: confirmed (signature mismatch and stores); corruption destination depends on incoming A4.

The sampler is not `u32(void)`: it writes through an output pointer supplied in A4. Evidence: `c0156f04 MV A4,A10; c0156f08 STW B0,*A4[0]` clears that destination; subsequent GPIO results are merged into it (`c0156f28 STW B0,*A4[0]`). Its stock caller supplies 11813308 explicitly: `c01570f4 MVK 3308,A10; c01570f8 MVKH 11810000,A10; c015710e CALLP c0156f00,B3 || c0157110 MV A11,A4`, then reads `c0157114 LDW *A4[0],A0` after restoring A4=A10. Existing controller code `c01a0010 B A11; c01a0014 ADDKPC ...,B3,4` passes no valid output buffer; the second call at c01a0018 also lacks one. Consequently the two purported bitmap return values are not valid sampler results and startup can overwrite an uncontrolled address before stock startup runs. Calling stock startup last does not preserve its behavior.

Proposed source fix (report only): declare the sampler as `void (*)(u32 *)`, allocate initialized local bitmap(s), and pass their addresses; consume the written bitmap, never the return register. Separately establish GPIO initialization before sampling, or move the latch after sampler/GPIO setup and before event processing. Two back-to-back reads are not timed debounce. Exact returned A4 and initialization ordering are traced separately below.

### 1.3 Sampler returns its destination pointer and runs before normal GPIO setup
Confidence: confirmed (A4 value, initialized base and call order); actual pre-setup pin levels unknown.

`c0157020 MV A10,A4; c015702e STW A0,*A4[0]; c0157030 CALLP c016e000,A3` leaves A4 equal to the caller's output pointer. The restore helper c016e000..e00e restores saved registers/stack, not A4. Thus, if the bad call returns, startup tests bit 9 of that pointer twice, not switch state. The second bad call reuses the same pointer. It does not return a defined default/uninitialized bitmap.

The GPIO reader uses an already C-initialized MMIO base: decoded `build/codex3/init_1180bd40.bin` has 11813214=01e26000; `118094a0 LDW *A5[0],A0; 118094b2 LDW *A5[8],A0` reads hardware directly. However, MainApp normally calls `c015d440 CALLP c0160ad8` inside stock startup; that routine programs GPIO (`c0160aea STH A0,*A4[10]`, further direction/output stores through c0160b4c). Normal sampler setup is later still: `c0134e18 CALLP c0134db8; c0134dc0 CALLP c01341e4; c0134200 CALLP c01570a4; c015710e CALLP c0156f00` with a real output pointer. The hook runs before both. Reading a pre-setup register is not proof of the eventual stable switch level; boot inheritance may make it work but is not a substitute for this order audit. Fix both defects: call stock startup first, then sample through valid local storage before entering the event loop, or place the latch after c015710e using its produced bitmap. Verify the intended hold timing for that later latch. No source was edited.

### 1.4 Dispatcher preserves the event frame and loop bookkeeping
Confidence: confirmed for the traced loop/compiled instructions; whole-program event-side effects are not claimed equivalent.

At c0134db8 MainApp reserves 24 bytes. Queue receive uses `c0134dd4 ADD 4,B15,A4`; controller dispatch saves another 8 (`c01a0252 STW B3,*B15--[2]`) then forms `c01a0254 ADD 12,B15,A4`: exactly the original event pointer. `c01a0260 LDW *++B15[2],B3; c01a0262 NOP 4` restores both stack and return link before branching to c0134dc4. All stack deltas here are multiples of eight. Normal mode tail-branches to c0127fe0 with B3 intact and returns its B14[27] selector to c0134df4. The asm only additionally clobbers caller-scratch A0/B31; it does not change B14 or the A10..A15/B10..B13 preserved set.

The controller-mode resume executes housekeeping c01537f4 before `c0134dcc STW 0,*B14[124]`, receives the next event, then `c0134de0 STW 1,*B14[124]`. That is the same cycle reached by both stock handler returns and the stock event-42 skip. No missing B14[124] restore is required in the wrapper. The loop retains no scratch-register result across that resume; the event lives on the preserved frame. Skipping handlers intentionally suppresses their screen/system actions too, and does not imply the whole application retains stock behavior. Housekeeping remains able to run c01537a8, including its system-event path; controller mode is not total isolation from all stock UI work.

### 1.5 Existing patched hook words retain targets and analog parallel instruction
Confidence: confirmed for bytes read from the existing BIN and existing disassembly; fresh dis6x rebuild remains blocked.

Independent PowerShell byte reads of `build/fw/res1_controller.bin` decode the CALLP signed 21-bit displacement against its 32-byte fetch-packet base: c0134e14=10d64012 -> c01a0000; c0134df0=10d68c12 -> c01a0240; c015ffd0=10804513 -> c01a01e8. Analog p-bit remains 1, adjacent c015ffd4 remains 9862 (`EXTU A0,24,24,A4`), and fetch header c015ffdc remains e5e08000. Thus A4 is produced in the same execute packet before entering the wrapper; changing the branch target alone does not sever that pairing.

Existing startup wrapper saves/restores B13 and A11:A10 (`c01a0000 STW B13,*B15--[2]; c01a0002 STDW A11:A10,*B15--[1]; c01a0054 MV B13,B3; c01a0058 LDDW *++B15[1],A11:A10; c01a005a LDW *++B15[2],B13`). B15 moves by 16 total, preserving eight-byte alignment. Analog wrapper c01a01e8..022c is a tail-branch wrapper with no frame or preserved-register writes: stock path branches to c014aef4, controller path tail-branches to cc. cc uses a 16-byte frame (`c01a006c STW B3,*B15--[4]`, restore c01a0094) for the three-byte message. The stock analog caller's live A10 is preserved, allowing `c015ffd8 STW A0,*B14[76]` and A10 return after the hook. No B14 modification occurs in these wrappers. This closes these calling-frame checks, not the sampler ABI bug or transport safety.

### 1.6 Hook tasks and MIDI lock ordering do not establish a bounded send
Confidence: confirmed for traced tasks/locks and unready branch; likely absence of an inversion on these direct hook paths, not a global deadlock proof.

Start/dispatch execute in MainApp (entry c0134e10). Analog notifications execute in AD task 11809004: callback call `1180910c LDW *A4[1],A0; 11809110 B A0` reaches c015f08c, then descriptor[9]=c015ffe8 and `c015fff0 CALLP c015ff60 || MVK 1,B4`. The two other direct calibration calls supply B4=0 (c0160044/c01600f0), suppressing c015ffd0. AD's serial lock B14[149] is released by `1180ac00 CALLP 1180b0f0` before returning the sample. MainApp dispatch has returned from queue receive before the hook. Controller analog bypasses stock c014aef4, so its B14[155] acquisition at c014af0c has not occurred.

Send lock order is outer B14[161] then inner B14[89]: `c01274d4 CALLP c0150b20 || LDW *B14[161],A4`, timeout -1 at c01274e0; `c0149df0 CALLP c014a094 || LDW *B14[89],A4`, with `c014a096 MVK -1,B4`. Worker c0149c14 also holds B14[89] while calling packetizer c01489a0 (c0149c8c), then releases it at c0149c98. No reverse 89->161 acquisition was established on that traced worker segment. Indirect callbacks/transitive transport waits remain outside a complete lock graph; 'short waits' is not justified merely by Task context.

Unready transport returns ffff63be (`c0144e00 LDW *A4[3],A0; c0144e02 CMPEQ 1,A0,A0; c0144e10 MVK 63be,A4; c0144e14 MVKH ffff0000,A4`). But the outer infinite-timeout lock precedes this check. Disconnect cleanup clears ready state at c0144e78; it is not proof that a send cannot wait for an existing owner. Ready sends append a possibly partial prefix without waiting for ring space; c01274cc then releases its outer lock and hides that result. Therefore: no explicit enumeration wait in the traced send path, fast rejection only after outer-lock acquisition, no unconditional fail-fast or bounded-latency guarantee. Proposed fix remains bounded producer state plus a separate transmitter, with whole-message reservation and disconnect handling (recon/17 A3).

Status: blocked: fresh isolated compile/dis6x forbidden by current executable/write constraints; exhaustive indirect lock graph unresolved. Existing-artifact hook audit found a confirmed startup ABI bug; no runtime-safety approval.

## 2. SDRAM gap c0187024..c01f4000

### 2.1 Known initialization and heap extents do not allocate the gap
Confidence: confirmed for inspected decoded ranges and direct constructor calls; not an exhaustive runtime ownership proof.

Scanned every existing `build/codex3/init_*.bin` destination plus decoded length: none intersects [c0187024,c01f4000). Inventory saved at `build/codex8/cinit-ranges.txt`. c0187024 is a record-table end, not a clear-until-RAM-end destination: `c0163718 MVK 6ef4,A3; c0163720 MVK 7024,B4` with c0180000 high halves; records supply separate destination B4 at c016376c and decoder handler at c0163780/3788. Thus that reference alone does not create a growing .bss/heap into the gap.

Direct constructor inventory (`build/codex8/heap-callers.txt`) finds the custom heap initializer at c015fe78 consuming descriptor base/size (`c015fe76 LDW *B4[4],A6; c015fe80 LDW *B4[3],B4`). Its known effect descriptors are the five fixed 0xa000 regions starting c01f4000 (or the independently relocated Slot 0), and output-EQ c00d2800; none grows backward into the gap. The one direct HeapMem constructor call at c0163078 explicitly supplies c0184a00 and 0x400 (`c0163068 SET B0,10,10,B0; c016306a STW B0,*B15[6]; c0163074 STW B0,*B15[5]`). The static c00f1800+0x8000 heap is likewise disjoint. Indirect allocator constructors and arbitrary effect memory writes are not ruled out by this inventory.

### 2.2 Computed c0000000 file-buffer offsets are bounded below the gap
Confidence: confirmed on the inspected normal insertion path (assuming its initialized metadata is intact).

A computed-user candidate really exists: `c014c118 MVK 0,A1; c014c120 MVKH c0000000,A1; c014c126 ADD A1,A0,A0; c014c12c CALLP c012b744` reads a file into c0000000 plus a running offset. But c014c0d0 obtains the previous entry end, and `c014c0d6 MVK 25,A1; c014c0d8 SHL A1,14,A1; c014c0e0 SUB A1,A0,A0; c014c0e4 CMPGTU B0,A0,B0; c014c0e8 [B0] BNOP c014c14c,5` rejects a file larger than remaining 0x64000-byte capacity. A separate 40-entry limit is checked at c014c0f0..f8. Initialization c014bef4 clears exactly 25<<14 bytes at c0000000 and c014bf0c clears 15<<6 bytes of descriptors at c0064000. The computed read/copy path is a bounded low-SDRAM pool, not evidence of occupation at c01a0000. This does not certify behavior with corrupted file metadata.

### 2.3 Boot flash reads pass through the AIS destination, with no gap staging found
Confidence: confirmed for the traced argument chain; all SPI/DMA side effects not exhausted.

Normal res5 loading passes section destination/length directly: `c022bb62 LDW *B15[3],A6; c022bb66 LDW *B15[2],B4; c022bb68 CALLP c01fda8c`. That wrapper saves B4 in A13 and forwards it at c01fdacc to c01fd8b8. Flash-read command 0x0b is built in a 16-byte stack frame (`c01fd8c8 STB A0,*B15[8]`); its payload read supplies the saved destination and length: `c01fd8f2 MV A11,A6; c01fd8f4 CALLP c022b2dc; c01fd8f8 MV A10,B4`. The SPI routine preserves that destination in A14 at c022b2f0 and uses state at c022dd28/c022ddc8. There is no intermediate c0187024..c01f4000 flash buffer in this traced chain. Stock AIS has no section there; the controller AIS deliberately adds one. Boot executes before main, not concurrently as an updater overlay, but DMA completion/teardown still needs full transitive proof before excluding every residual writer. Merely observing disjoint res5 code is insufficient.

### 2.4 Cache coverage and generic DMA prevent an unconditional unused verdict
Confidence: confirmed for cache coverage/generic destination support; overall unused status unknown.

MAR setup does cover the gap: `c0159fa0 MVKH c0000000,A18; c0159fa8 B c016c420; c0159fc4 ADD A17,A18,A18` advances 16 MiB regions; `c016c454 STW A6,*A7++[1]` writes MAR attributes, not a destructive memory-test pattern. It neither allocates the gap nor proves ownership. Known audio PaRAM destinations are the 11f03xxx ping-pong buffers (recon/16 C1); PaRAM publication is generic: `1180a5a4 SHL B0,5,B0; 1180a5ae SET B0,14,14,B0; 1180a5b4 CALLP 1180ba70` copies 32 caller-provided bytes into 01c04000+32*index. Serial setup calls that builder at 11806724, so excluding audio buffers does not exclude all DMA destinations. USB likewise accepts a caller buffer (`c01202e2 STW A6,*B4[4]` in a CPPI descriptor), rather than hard-coding every target.

No destructive RAM test covering the gap was identified in the inspected startup/constant candidates; that is a scoped negative result, not whole-program exclusion. Candidate inventory is `build/codex8/computed-range-candidates.txt`. Known effect allocation, zeroing and file pools are disjoint, and no concrete stock owner of the gap was found. Verdict: **unknown because generic DMA destination provenance, indirect heap creation, every computed store/memory-test path, boot DMA teardown, address aliasing and loaded-effect behavior have not been exhaustively bounded**. Do not promote likely-free padding to a reserved runtime region or certify controller residency from this scan.

Status: blocked: whole-program computed-address/DMA and loaded-module bounds are missing; scoped verdict is unknown, with no concrete stock owner found.

## 3. USB audio driver and silence-stream patch list

### 3.1 Descriptor pointers cannot simply grow in place; 192-byte response storage is likely sufficient
Confidence: confirmed pointer bound/count check and wLength logic; likely 512-byte response allocation (original linker size unavailable).

c0160ec0 builds at c00643c0 and writes through index 13 (`c0160ff6 STW A7,*A4[13]`), returns its pointer through A6, and rejects count >14 (`c0161044 CMPLT 14,B0,B0; c0161050 MVK ffff8acf,A0`). The next independently used object is c00643fc, explicitly cleared for four bytes at c0154c18/c0154c48; effect entries start c0064400. Thus the available interval is only 60 bytes, at most 15 pointer words including the null termination consumed by callers. The normal builder reports 14 descriptor pointers including device; stock configuration uses 13. Appending the ten UAC descriptors needs 24 populated pointers including device plus a null (100 bytes); relocate the array and raise its bound, or replace all fragment consumers coherently with a contiguous-descriptor design. Merely changing wTotalLength overruns the old pointer storage.

Response buffer starts c0119fb0; next independently referenced object is the alternate-setting array at c011a1b0 (`c0134e7c MVK a1b0,A5; c0134e8c LDB *A4[A5],A0`). Their 0x200 spacing supports a 512-byte control buffer, but this stripped image does not supply its allocation symbol/size. No capacity guard appears in the inspected configuration copy. It selects min(wTotalLength,wLength): `c013506c LDHU *A5[1],B3; c0135070 LDHU *A7[3],B5; c0135076 CMPGTU B3,B0,B0; c0135080 EXTU B5,16,16,B3`, clips each fragment to bytes remaining and copies at c01350c6/50ca. c0135108 passes B3 as A6 to c015af48. A 192-byte result ends c011a070, below the next known object, and the loop can serve it after pointer-array expansion. Exact buffer capacity remains likely rather than linker-proved; reserve an explicit >=192-byte buffer in the new patch allocation if a proof is required, and clamp/validate lengths independently of host wLength.

### 3.2 Stock supports alternate-setting requests, but is not ready for IF2/IF3
Confidence: confirmed standard decode/alternate matching; class-request fallback is conditional on registered callbacks.

Standard request table c0180210 indexes bRequest: index 10=c0134e68 (GET_INTERFACE), 11=c0135940 (SET_INTERFACE). Common decoder c01359e4 reads SETUP via c0122370, extracts recipient and type, first attempts a registered class/interface callback (c0135a52 loads callback[3], c0135a60 calls it), then falls back for standard type at c0135a90..aa6. Nonstandard requests with the fallback error become ffff8acc at c0135a8c; any nonzero final result stalls EP0 IN through `c0135ab8 CALLP c0120ef8 || c0135ac0 MVK 128,A4 || c0135ac4 MVK 1,B4`.

GET_INTERFACE requires B14[11] configured and returns the byte at c011a1b0+wIndex (`c0134e78 LDHU *A4[2],A4; c0134e8c LDB *A4[A5],A0`). SET_INTERFACE writes wValue there before calling c01357c8 (`c013596e STB A0,*A4[A5]; c0135970 CALLP c01357c8`). That walker explicitly matches interface descriptor type 4, bInterfaceNumber and bAlternateSetting (`c0135840 CMPEQ 4,A0,A0; c013584c CMPEQ A0,A10,A0; c0135858 CMPEQ A0,A11,A0`) and configures its endpoint descriptors through c01212e0 at c01358b4. Thus 'no alternate-setting support' would be false. However, missing-match paths return without an error result checked by SET_INTERFACE, and alt0 with zero endpoints returns at c0135880 without an explicit disable of previously active alt1 traffic. Add validation before state writes and explicit alt1->alt0 stop/flush behavior.

Interface ownership lookup c015c788 accepts low-byte interface indices <6, reads c011aac0[index], and rejects -1. Registration c015c66c hard-codes only IF0/IF1 and OUT3/IN4; reset c015c638..64a initializes only two interface mappings, while the decoded remaining words initially contain zero. IF2/IF3 can therefore alias registration slot 0 rather than reach a new UAC handler. Existing standard fallback can address them but is not a correct UAC implementation. Unsupported class requests stall when that callback returns the fallback/error; the actual callback must also be audited before asserting every UAC bRequest always stalls. Patch IF2/IF3 routing explicitly, initialize all mapping/alternate entries, validate recipient/index/length/value, and reject unsupported fixed-rate UAC controls deliberately. Current one-byte alternate-array clearing at c01359cc..da/c013566c..7a also needs replacement for all four interfaces.

### 3.3 Stock endpoint setup already sets ISO; its FIFO repacker moves MIDI
Confidence: confirmed transfer-type/CSR logic; proposed fixed-tail PIO allocation is unimplemented.

`c0121412 AND B1,3,B0; c0121414 CMPEQ 1,B0,B0` identifies isochronous attributes (including proposed 0x05), records the flag at endpoint-state[2], then `c0121434 XOR 1,A0,A1; c012143a SHL A1,14,A1; c0121440 SHL A0,6,A0; c0121442 OR A0,A1,A0; c0121444 STH A0,*B4[0]` writes TXCSR. Here A0 before the shift is 209: base CSR=0x3440; ISO adds 0x4000, yielding 0x7440. This is actual stock ISO-mode support, although stock descriptors never select it. It also enables DMA-related bits, so do not reuse that entire CSR value for a PIO producer. [TI SPRUFM9H, sections 2.7.1.4.1 and 4.35](https://www.ti.com/lit/ug/sprufm9h/sprufm9h.pdf) identifies ISO bit 14 and the separate DMA controls.

Stock setup calls the shared FIFO allocator at c012146e onward, recomputing all endpoints from byte 64 (`c01214c0/c01214c6` write TX/RX FIFOADDR). Adding double-buffered TX1=256*2 through it shifts RX3/TX4 by 512 bytes; it cannot preserve their old addresses while using this unchanged repacker. A dedicated allocation at unused bytes 0x140..0x33f can preserve RX3=0x040..0x0bf and TX4=0x0c0..0x13f: TX1 FIFOADDR=0x28, TXFIFOSZ=0x15, TXMAXP=180. Total occupied end is 0x340 (832 bytes). Patch/bypass the repacker consistently for TX1, reserve that tail across later endpoint configuration/reset, and flush while quiescent. PIO must disable TX1 DMA ownership and set/clear TXPKTRDY with correct CSR semantics; endpoint number availability alone does not make that integration safe.

### 3.4 SOF runs in CPU interrupt 7, not the priority-13 USB Swi
Confidence: confirmed registration/vector chain and context; PIO worst-case timing unknown.

USB registration passes {callback=c011fc8c, CPU interrupt=7, event=19, enable=1, mask parameter=16}: c0122290 stores callback, `c0122292 MVK 7,B0`, c0122296 selects 19. c014a524 copies input[1] and callback into the argument pair consumed by c01655c0 -> c0168d00. c0168d00 indexes the per-interrupt table using that 7, then c0169ca0 generates a vector at ISTP+32*interrupt (`c0169cd0 SHL A4,5,B7`) to the Hwi dispatcher c015ec80. Event routing parameters are supplied separately. The SOF path executes `c011fca2 EXTU B0,12,31,B0; c011fcb2 STW B0,*A4[0]; c011fcb4 CALLP c016f770` before the deferred Swi post at c011fd28. Veneer c016f770 branches to 11818e80 (008ca362, BNOP B3,5). Priority designation is CPU INT7/event19; USB Swi priority13 and audio Swi priority15 are different scheduling levels, not the SOF hook's priority. Exact nesting/mask behavior needs a complete Hwi-dispatch audit.

180 bytes require 45 word FIFO stores plus CSR/frame bookkeeping; that is a bounded loop, not a proved cycle budget. Bus wait states, interrupt masking/nesting, cache misses and audio deadline interference are not established by static instruction count. A Hwi delays Swis while running, including audio. Verdict on 'fits there': unknown without a worst-case bus/dispatch timing bound; do not claim 45 cycles or guaranteed 1 ms completion. For a silence prototype, precompute zeros, use fixed bounded PIO stores and direct endpoint registers where possible, avoid locks/allocators/bulk APIs, and retain overflow/missed-SOF counters. No timing or hardware test was run.

### 3.5 Registered MIDI callback short-circuits SET_INTERFACE and rejects UAC class requests
Confidence: confirmed for normal MIDI registration; supersedes the assumption that all interface requests reach the generic walker in 3.2.

Registration at `c01521a8 MVK 137c,B4; c01521ac MVKH c0180000,B4; c01521b0 CALLP c015afa0 || MVK 6,A4` installs c018137c. Its request callback at +12 is c0151ed0 (word at c0181388). That routine defaults to ffff8a5b and immediately returns it for a nonzero request-type argument (`c0151ed4 MV A4,B0; c0151ed8 MVK ffff8a5b,A1; c0151ee4 [B0] BNOP c0151f90,5`). Therefore UAC class requests (type 0x20) on mapped interfaces reach common fallback and STALL as traced in 3.2. IF2/IF3's initial zero mapping may alias this same registered slot, which likewise rejects class type; invalid mapping also fails/stalls. No UAC class handler exists on this path.

For standard type, however, `c0151eec CMPEQ 11,B1,B0; c0151ef0 [B0] BNOP c0151f5a,5` recognizes SET_INTERFACE and simply submits a zero-length status reply (`c0151f64 CALLP c015af48`, A4=128, A6=0), then returns success. It does not inspect wValue/wIndex or configure alternate endpoints. Common dispatch therefore does not reach c0135940 for these mapped interfaces. Stock has generic alternate matching code but normal MIDI registration treats SET_INTERFACE as a no-op ACK. The silence patch must change this callback/routing as well as the generic standard handlers, or IF3 alt1 will never activate. GET_INTERFACE falls through to the generic byte lookup. This clarifies actual normal behavior beyond the table-only trace.
