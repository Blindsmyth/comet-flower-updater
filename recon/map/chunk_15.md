## Open questions (USB priority follow-up)
- The fact sheet's "c015e9d0 size 1200" is not one function: it is usb_ifconfig_reset_state (144 bytes, true USB reset/deconfigure step), usb_ifdesc_endpoint_scan (hidden, ~500 bytes, SET_CONFIGURATION/SET_INTERFACE descriptor parsing and endpoint discovery), and bios_hwi_context_switch (hidden, ~512 bytes, the generic DSP/BIOS interrupt/task full-register-save dispatcher -- unrelated to USB, just laid out adjacently). Neither hidden half was flagged by hidden_starts.py (both are reached only after a CALLP to rts_regs_restore/c016e000, which the tool's heuristic does not treat as a function end).
- USB event coverage in this chunk: no branch anywhere in c015e880/e924/e9c0/e9d0/ea80 dispatches on a bus RESET, SUSPEND, RESUME, or SOF signal name or bit; all four ptr@-registered handlers (c01807a0/a4/a8/c8) and the reset/descriptor-scan pair are consistent with standard **control-request handling** (GET/SET_CONFIGURATION, SET_INTERFACE class of requests) reached from the USB control endpoint, not with the asynchronous bus-event path. No MMIO 0x01e00000 (USB OTG controller register block) or CPPI access was found anywhere in chunk 15's address range (c015c3ce..c0163040) -- the only MMIO in this chunk is 01810000 (c015d414, unrelated peripheral reset write), 01844000 (c015ee80, L2 cache controller, not USB), and 01800000 (c01604a0, an interrupt-enable/IER list walk, also not USB). The real USB OTG/CPPI/endpoint-FIFO hardware access, and any bus reset/suspend/resume/SOF handling, must live in functions outside this chunk's range (the usb_* named callees such as c0122ad0, c01229e8, c015b128, c0138660, c01359b8 are themselves defined elsewhere).
- Where a USB audio stream would need to be stopped: usb_ifconfig_reset_state (c015e9d0) is the natural stop point -- it already resets per-interface/endpoint bookkeeping (usb_endpoint_records_reset c0138660, the alt-setting array at c011a1b0 via c01359b8) and runs on SET_CONFIGURATION/SET_INTERFACE before usb_ifdesc_endpoint_scan re-discovers endpoints for the new configuration. Any code that currently starts/continues an audio-streaming EDMA transfer tied to the OLD endpoint assignment should be torn down inside or just before this reset step, since usb_ifdesc_endpoint_scan immediately overwrites the endpoint list afterward. c0160120 (called at the end of usb_ifdesc_endpoint_scan) looks like a generic string/byte-scan utility (SPLOOPW replacing a found byte with 0x2e='.'), not a streaming control point -- its other callers (c015b620, c0169b60) are MIDI-rooted, not USB, so it is likely reused incidentally for a descriptor string field rather than endpoint enable/disable logic.
