# Chunk 01 function map: 118072ac..1180b020

Summary: this range is the L2 (0x1180xxxx) task/driver region covering the
switch and knob input subsystems (normal-speed 10-button GPIO sampler and
its debounce/remap path, the two-footswitch sampler, the four-knob relative
encoder/accumulator path), the AD task's external serial converter read
(GPIO-bit-banged handshake plus i2c_write), the McASP/EDMA audio-engine
builder and ISR dispatch, the zero-target gain-ramp family, MIDI compose/
queue helpers shared with MainApp, LooperUI mute-group helpers, UpdateUI
screen-list/scroll helpers, and a block of small MainApp/UI orchestrators
entered through the c016e020/c016e000 save-restore pair. Most routines in
the low 1180axxx addresses are thin leaves or glue with few or no internal
branches; call-graph position and B14 slot reuse are the main evidence for
those, so many rows below are "likely" rather than "confirmed". Three
functions in this range are already named in recon/map/00_library_kernel.md
and are skipped here (see 00): 118093c0, 1180a2a8, 1180ad68.

## Data
- `0x1181268c`: audio-ramp disable/enable flag — set by 1180a350 (ramp_flag_set_1268c), cleared by 1180a340 (ramp_flag_clear_1268c); gates whether 1180a4c4/1180a4a0 wait for an audio-Swi handshake or write directly (recon/16).
- `0x1181312c`: a second, distinct generic flags word — set/cleared via 1180a660/1180a684 (OR/ANDN of a caller-supplied mask), and also has bit0 set/cleared inline by 1180a6a0 (used as a "5-slot update in progress" guard). Not the same word as 0x1181268c.
- `0x118115a0`: table indexed by (value*84) (fixed_scale_mul_84 stride), written 2 words/record by 118072ac via veneers 1180b830/1180ba40.
- `0x11811ca8` region, offset 105*8=840 bytes further in: written by 11807310 via the generic block-copy veneer 1180ba70, keyed by the function's arg0.
- `0x11813430 + 4*i` (i=0..3): the four rotary-knob signed-delta accumulators, read/cleared by c0169554 and updated by 1180afc0/1180afe0 (recon/15, confirmed).
- `0x118132e4/e8/ec`: two-footswitch raw / masked / prior sampled-state bytes (recon/15).
- `0x1181330c`: ten-normal-button sampled/masked bitmap compared each poll by 118076c0's task body (recon/15).
- GPIO_base `01e26000` (from initialized word `11813214`): used by 11809484's `*(GPIO_base + 40*(pin>>5) + 32)` bit read (recon/15). Pins used in this chunk: GPIO90 (AD serial clock/latch, 11809474), GPIO3/GPIO5 (footswitches, 1180954c), 27/24/26/37/38/86 (normal buttons via 118094c4, default 0 for index 6).

## Open questions
- Hidden-start pass 2026-10-09: 5 rows added, 5 host rows rewritten, 0 false positives.
- The loop bound of exactly 5 appears independently in both 11807310 (per-slot config write) and 1180a6a0 (guarded parameter apply). This strongly suggests the firmware's 5-effect-slot architecture, matching the project's "5-slot patch" goal, but no symbol or comment in this chunk proves the loop indexes slots rather than some other 5-element table (e.g. 5 MIDI channels). Worth cross-checking against c014ff44's 16-byte-stride 0x11f03ad0 table (already flagged by 00 as "per-slot (5 effect slots?) record accessor") the next time either is revisited.
- 1180ae40's exact action inside 11807310's 5-iteration loop was not traced (it's a 96-byte leaf with no recorded calls, so its body itself must be read, not just its callers).
- 1180856c/11808ac0/11808560 (AD-rooted) and 118088d0/11808838 (i2c_write, MainApp-rooted) both sit in the same address neighborhood and both end up calling the shared MMIO-poke helpers c01609f0/c0160a04..c0160a84 (also used by MainApp's 118086e4) — it is not yet established whether the AD cluster and i2c_write share the same physical bus/peripheral or are genuinely separate (bit-bang GPIO vs. a real I2C controller).
- 11809f00 and 1180a130, both called once from inside 1180abc0 and both calling big_subsystem_init, were not distinguished from each other — likely two different AD one-time-init branches (cold-boot vs. re-init?) but this is unconfirmed.
- The usb-descriptor/string-formatting cluster (11807ea0 through 11808440) is inferred purely from callee names (usb_desc_table_get, fmt_render_wrapper/2, fixed_scale_mul_84) and was not independently disassembled in this pass; a future pass should confirm what field or string it actually renders.
- 1180a734's status-struct bridging role sits among otherwise-MIDI-tagged neighbors (1180a720,1180ace8,1180acd4) — it may actually belong to a different (error/status) subsystem that happens to be reached from MIDI call sites, rather than being MIDI-specific itself.
