## 3. Waiting on the owner (next step)

Probe measurements. Instructions are in the last session message; summary:
1. Probe 10, Tone = 1 → **tuner reading** (A4 = 440.0 Hz confirms 44.1 kHz).
2. Raise Probe 10 Load → **Load value where the beep crackles.**
   Each step is 1600 cycles/block (8-cycle dependent loop, read from the
   disassembly), so `limit_cycles ≈ value × 1600`.
   Block period 362.8 µs, so MHz ≈ cycles / 362.8.
3. Stack Probe 30s, then Probe 10s, in one patch → **patch dspload budget**.

Then the **Green 808X play test**. Its estimated cost is ~74k cycles/block,
from the compiled schedule, excluding memory stalls. If test 2 breaks up at

## 5. Safety rules (keep)

- **AUTO SAVE off** on the pedal during experiments.
- Never save a patch with an **untested** effect; it is a known brick path.
  Recovery net: the G1 firmware-update mode (hold both footswitches while
  connecting USB) plus Zoom's v2.00 updater (untested).
- Ask the owner before every new class of write. The established workflow
  (writetest → install → replace) has been approved repeatedly.
- Never leave a transfer half-done: keep the pedal powered if a tool reports
  UNRESOLVED.
- Stock state size precedent: plain G1 effects use ≤ 392 B of contiguous
  state undeclared, which is why `build_g1.sh` caps at 392.

## 6. Next steps (in order)

1. **Read the probe results**, size 808X, and log the CPU / budget / sample
   rate in `recon/06`.
2. **Optimise 808X if needed.** The Newton step is 154 cycles, latency-bound.
   Options:
   - ~~one exp plus a reciprocal instead of two exps~~: tested 2026-10-05.
     Bit-identical output (-136 dB), but the cl6x schedule gets *slower*
     (Newton loop 201 -> 222 cycles): the two exps run in parallel, and the
     reciprocal adds latency. The loop is not software-pipelined
     ("Resource bound too large"); its cost is latency x iterations
     (8 x 16 x 3 iterations, ~77k cycles/block). **Iteration count is the lever.**
   - fewer iterations: a plain warm start with 2 steps is -37 dB off the
     3-step solve (alias -49 dB); linear-extrapolation starts are worse
     (-18 dB). A table-based start in normalised (c, r) is the next try;
   - a lower exp polynomial degree;
   - a better initial guess, allowing 2 steps.
   Re-verify every change against `ts808_accuracy`.
3. **Owner A/B: Green 808 vs 808X** by ear. Then decide what Comet Flower
   gets back. The Shockley stage would improve the desktop and mobile
   versions too; that is the owner's call.
4. **Exact tone-stage MNA.** It needs the TS808 tone-stage netlist; the
   ElectroSmash text gives it only as an image.
5. **Decode entry-struct fields [5]–[8]** (delay, reverb, pitch and amp
   memory requests). This unlocks delays, reverbs and cab ports from Comet
   Flower.
6. **G1 input voltage calibration.** It needs a reamp/loop cable or Zoom's
   USB-audio driver. It is the same unknown as Comet Flower's R1 blocker.
7. **Cleanups:**

## 7. Key facts (quick reference)

- DSP: TMS320C6745**DPTP3**. Silicon revision 3.0, commercial grade, speed
  grade "3": 375 MHz per the datasheet nomenclature; TI's product page says
  456. The real clock is set by Zoom's firmware PLL and is not yet measured.
  Flash: MX25L3233F, 4 MB.
- Audio callback: 16 frames × 2 channels, float32, in place at `ctx[1]`.
  44.1 kHz is assumed (stomphacks, MS Plus); the probe tone confirms it.
- G1 container:
  - target bit `0x02` (present in every stock effect);
  - header bytes 0x10 = 01, 0x18 = 80, 0x58 = slot count;
  - ICON block: 1-bpp BMP, 23/24×30;
  - the trailer is packer filler, and the pedal does not check the CRC.
- The **slot picture** is ELF image-list entry 0, in LCD page format (8 rows
  per byte, LSB at the top). A blank picture shows as "BYPASS"/empty.
- Patch slots:
  - id `0x0` = empty;
  - id `0x1` = the second half of a double-width effect.
- Zoom TS Drive (for comparison):
  - 4x IIR oversampling;
  - an asymmetric piecewise-quadratic clipper (+0.925 / −0.487);
  - pre-clip gain of only 3.5–26x;
  - aliasing −35 dB, against our −55 dB.
