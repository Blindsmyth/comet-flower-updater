- **Update-mode SysEx wire protocol fully decoded (send + receive)** (`recon/26_update_mode_protocol.md`,
  `tools/update_mode.py`, `tests/test_update_mode.py`): statically disassembled the x86 updater.exe
  end-to-end:
  - Worker lifecycle (`0x404630`): Universal Device Inquiry (`F0 7E 00 06 01 F7`) -> Identity Reply
    copies `6E 00 0D 00` into `.data 0x44bc0c` via `memcpy` at `0x4047dd` (**`MODEL_BYTE` is `0x6E`**, not `0x00`),
    Enter Update Session (`F0 52 00 6E 01 F7`), Stage Runner (`0x403aa0`), and Exit Update Session (`F0 52 00 6E 04 F7`).
  - Pre-loop Flash Read (`0x403b00..0x403d1c`): `F0 52 00 6E 60 30 <0x27FFC:5B> <4:5B> F7` reads the
    4-byte boot version string (`"1.00"`) at the end of the `0x28000` boot region; if equal to
    `Resource_0x8E + 0x27FFC`, `0x403c4f` sets `write_boot = 0` (`[ebp-0x18] = 0`) and **skips** any
    stage with `addr == 0`. Fixed `tools/make_boot_logo_updater.py` to patch `0x403c4f` (`0 -> 1`) so
    `COMET FLOWER BOOT LOGO - bud - run once.exe` (`91c67870`) actually writes the boot logo.
  - Receive-side reply parser (`0x403ee0`, jump table `0x4041b0`): `cmd == 0x00` (`F0 52 00 6E 00 <status> F7`,
    `0x00` = ACK, `0x0B` = not in update mode, other = error/retry), `cmd == 0x02` (write ACK), and
    `cmd == 0x60 0x04 0x30` (7-bit packed flash-read reply + CRC32). Implemented in `tools/update_mode.py`
    (`parse_reply`, `unpack7`, `build_identity_inquiry`, `build_enter_session`, `build_exit_session`).
