### Finding 2: Declared DSP Load (`dspload`) Field Location and Distribution

- **Claim**: The declared DSP load (`dspload`) is located in the tagged block `INFO` at payload offset `0x10..0x13` (bytes 16..19 of the block payload, immediately following the 4-byte class word and 12-byte group label). It is encoded as a 32-bit IEEE 754 little-endian float (`struct.unpack('<f')`). Every stock file possesses an `INFO` block with a payload length of exactly 20 bytes.
- **Evidence**:
  - `tools/zd2_set_dspload.py` (lines 18–35): locates tag `b"INFO"`, reads `offset + 8 + 16`, and packs/unpacks `<f`.
  - `src/zd2tools/models.py` (lines 25–29, 44–51): parses `word0` (`<I` at 0..4), `group_text` (latin-1 at 4..16), and `dspload` (`<f` at 16..20).
  - `build/fw_rnd/F2/survey_output.txt` (lines 168–180): exhaustive analysis of all 98 stock effects confirms:
    - Minimum stock dspload: **9.13** (`PDL_VOL.ZD2`, pedal volume)
    - Maximum stock dspload: **93.92** (`UK30A_1U.ZD2`, Vox AC30 amp model)
    - Median stock dspload: **22.76** (`MA2X12.ZD2`, cabinet model)
    - Mean stock dspload: **35.01**
- **Confidence**: Confirmed. Structure verified in code and empirical binary parse.

### Finding 3: Parameter Storage Architecture and Label Representations

- **Claim**: Effect parameters and labels are stored in four distinct structures across the container, ELF, and preset system:
  1. **ELF `.const` Parameter Table (Firmware & Pedal UI Source)**: Stored in the TI C6000 ELF `.const` section inside the `DATA` block. The table opens with an `"OnOff\x00"` record and consists of contiguous 56-byte records (`PARAM_RECORD = 56`, 14 little-endian 32-bit words). Its structure is:
     - Bytes `0..11` (words 0..2): Parameter label as a 12-byte NUL-terminated/padded C-string buffer.
     - Bytes `12..15` (word 3): Maximum integer value (uint32 LE; e.g. 100, 3018, or `0xFFFFFFFF` for the effect name record).
     - Bytes `16..19` (word 4): Default integer value (uint32 LE).
     - Bytes `28..31` (word 7): Edit handler callback function pointer (relocated via ABS32).
     - Bytes `48..51` (word 12): Flags bitfield (e.g. `0x16` indicating stock volume logarithmic taper).
     The entry stub `Dll_<Name>` returns a pointer to this table in register `A4[1]`, which the pedal firmware reads directly for display and knob editing. The table has record 0 = `OnOff`, record 1 = effect name header, followed by records 2..N for user knobs.
  2. **`PRME` Tagged Block (PC / Guitar Lab English Metadata)**: Standalone tagged container block containing JSON: `{"Parameters": [{"name": "...", "explanation": "...", "blackback": bool, "pedal": bool}]}`.
  3. **`PRMJ` Tagged Block (PC / Guitar Lab Japanese Metadata)**: Standalone tagged container block containing JSON with Japanese text for parameter names and parameter help text.
  4. **`EDTB` Preset Record (Preset Parameter Storage)**: In pedal preset data (`FLST_SEQ.ZT2` / preset dumps), each of the 5 patch slots occupies 24 bytes (192 bits). Bit 0 is the on/off state, bits 1..29 hold the 29-bit effect ID, and the remaining space encodes up to 12 parameters packed into 150 bits with bit widths `[12, 12, 12, 12, 12, 8, 8, 8, 12, 12, 12, 12]`.
- **Evidence**:
  - `src/zd2tools/elfinfo.py` (lines 12–14, 108–129): defines `PARAM_RECORD = 56`, parses 12-byte label, max, default, handler, flags.
  - `recon/02_g1x4_abi_comparison.md` (lines 20–25): confirms C6000 ABI matching G1 stock and stomphacks stubs (`A4[1]` param table).
  - `tools/ua_bench.py` (lines 49–51, 135–141) and `tools/g1presets.py` (lines 26, 75–77): defines `PARAM_BITS` for 12 knobs in 24-byte `EDTB`.
  - `build/fw_rnd/F2/survey_output.txt` (lines 185–201): verified across all stock files.
- **Confidence**: Confirmed.

### Finding 4: Parameter Limits, Label Lengths, and Page Alignment in Stock Effects

- **Claim**:
  1. **Maximum Parameter Count is 9**: The absolute maximum parameter count across all 98 stock effects is **9**. Zero stock effects have more than 9 knobs.
     - Single-slot effects (82 effects, `0x58 = 1`): **Every single one has exactly 4 knobs** in its ELF parameter table.
     - Double-width effects (16 effects, `0x58 = 2`): **Every single one has exactly 9 knobs** in its ELF parameter table.
     - **Padding with `Dummy`**: When a double-width effect has only 7 real parameters (e.g. `BGMK1_1U`, `FDBMAN1U`, `HW100_1U`, `MS800_1U`, etc.) or 8 real parameters (e.g. `FD_TWR1U`, `GTGEQ71U`, `PHASDL1U`, `TPEC3_3S`, etc.), Zoom's build tool explicitly pads the ELF table to exactly 9 entries with records labeled `"Dummy"`. In contrast, the `PRME` JSON block lists only the 7 or 8 real parameters.
     - **Hardware Cause**: The G1 Four user interface arranges multi-page effect controls in pages of **3 parameters per page**. A 2-slot effect is allocated exactly 3 pages of 3 parameters (3 × 3 = 9). The padding guarantees that every page has 3 valid record pointers.
  2. **Longest Label is 8 Characters**: The longest parameter label across the entire stock corpus is **8 characters**: `"D57:D421"` (used in 13 cabinet models to denote dual mic selection Shure SM57 / Sennheiser MD421).
     - Label character length distribution: length 1: 1 label (`W`), length 2: 2 labels (`Hi`, `Lo`), length 3: 20 labels, length 4: 30 labels, length 5: 35 labels, length 6: 6 labels (`MidCut`, `DryMix`, `Manual`, etc.), length 7: 0 labels, length 8: 1 label (`D57:D421`).
     - No stock effect ever uses a 9-character or longer label, even though the record buffer is 12 bytes.
  3. **Parameter Max Values**: Range from `1` (binary toggle/bypass switches) to `3018` (millisecond delay time in `DELAY_3S`, `ANDLY_3S`, `MODDELAY`). The top distinct maximum values are: 3018, 3006, 2014, 1503, 1411, 1005, 931, 562, 199, 110, 101, 100.
- **Evidence**:
  - `build/fw_rnd/F2/survey_output.txt` (lines 202–226): empirical census of all 98 stock effects.
- **Confidence**: Confirmed.

## Answers

### Question 1: Slot limit and effect list (Why is header-5 hidden while header-2 is offered?)
- **Answer**:
  In the entire stock corpus across both firmware 2.00 backup files and updater bench files, header byte `0x58` only ever takes values `1` (single slot) or `2` (double-width 1U amps, PhaseDly, TapeEcho3, Gt GEQ 7). There are **zero stock effects with slot count 3, 4, or 5**.
  The effect-list builder in firmware tests whether an effect can fit into the patch. Because stock effects never exceed 2 slots, the check is bounded by a maximum of 2, or checks against available patch slots with an upper ceiling of 2. `CFM2P` and `CFMPRE` declare `0x58 = 2` (matching stock double-width effects), so the firmware recognizes them as valid double-width effects and displays them. `CFM5P` declares `0x58 = 5`, which fails the `<= 2` check and is rejected/hidden from the menu.
- **Can a firmware patch change it?**: Yes. Patching the comparison instruction or table index in the effect list filter (handled by Job S1) can allow effects declaring `0x58 > 2` to be offered.

### Question 3: Per-effect limits (40 KiB heap, 12-param maximum, 3-params-per-page)
- **Answer**:
  - **12-parameter limit**: The hard 12-parameter bound originates in the preset record layout (`tools/ua_bench.py` lines 49–51, `tools/g1presets.py` line 26). The preset `EDTB` block reserves exactly 24 bytes (192 bits) per slot. After bit 0 (on/off) and bits 1..29 (effect ID), the remaining 162 bits are allocated to a 12-element bitfield array:
    `PARAM_BITS = [12, 12, 12, 12, 12, 8, 8, 8, 12, 12, 12, 12]` (total 150 bits).
    This establishes an architectural maximum of 12 parameters per slot that can be saved in a preset. Stock effects only utilize up to 9 parameters (or 4 for single-slot), but the transport and preset infrastructure was engineered for up to 12.
  - **3-params-per-page limit**: In stock double-width effects, when the effect has 7 or 8 parameters, Zoom's build tool explicitly pads the ELF `.const` parameter table to exactly 9 entries using `"Dummy"` records. This proves the firmware UI operates on rigid 3-knob pages (3 pages × 3 knobs = 9 knobs).
  - **Label lengths**: The C-string label buffer in the ELF `.const` record is 12 bytes (`PARAM_RECORD = 56`, words 0..2). Stock labels never exceed 8 characters (`D57:D421`), with 98% being 1 to 6 characters. Our DIY `CFMPRE` uses 9-character labels, which fit the 12-byte buffer but exceed stock conventions and may cause screen clipping.
- **Can a firmware patch change it?**: The 12-knob limit is bound to preset serialization (`EDTB` 24 bytes). Changing beyond 12 would break preset compatibility. The 3-params-per-page layout is tied to screen rendering geometry and encoder count.
