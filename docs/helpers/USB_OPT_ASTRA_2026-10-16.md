## A3. 24-bit FIFO feasibility
### A1 finding 1: descriptor length and completion flag (confirmed)
The configuration handler clips wTotalLength to wLength, gathers descriptor bytes into c0109fb0, and passes an equality flag to c015af48. For 192 versus 255 this flag is zero; lower-layer behavior is traced next.
Evidence: c013506c `LDHU *A5[1],B3`; c0135070 `LDHU *A7[3],B5`; c0135076 `CMPGTU B3,B0,B0`; c0135080 `EXTU B5,16,16,B3` (only if requested length is smaller); c01350ca `STB B0,*B4++[1]`; c0135108 `MV B3,A6`; c013510a `CMPEQ B5,B3,B1`; c013510c `CALLP c015af48,B3` with c0135110 `MV B1,B6`, A4=128, A8=-2, B8=0, A10=0. The c0122380 access mentioned in the brief is a setup FIFO **read**, not the reply write (`LDW *A4[0],A1`).
### A1 finding 2: explicit terminating ZLP path (confirmed, static)
Yes: the 192/255 response is continued after its third full packet and queued as a zero-byte fourth packet. It does not finish by placing DATAEND on the third full packet.
Evidence: c015af78 stores B6 (the equality flag) at request word 0; c01388d4..88ea copies that request to endpoint-record+12, making it record word 3. c015b2c8 loads remaining bytes from record word 4; c015b2ce loads data pointer from word 6; c015b2d0 `CALLP c0120fb0,B3`. c015b2e6 `SUB A0,B0,A2` subtracts bytes sent; c015b2e8 stores remaining bytes. At c015b330..33a zero remaining AND return ffff8a59 (full packet) selects c015b340 `LDW *A4[3],A0`; c015b342 `[!A0] BNOP c015b364,5` leaves the transfer pending when the equality flag is zero. No disable/completion occurs on that branch. Event dispatch c01383e6 `LDW *B5[B4],B0` uses table c01807a0; ELF word 6 is c015b2b4 (the same send routine).
The EP0 interrupt state=1, TXPKTRDY clear path c0121b78..1b8a branches to c0121c08 (continuation event, inspected next). Low-level sender c0120fb0 recognizes endpoint 128 at c0120fc0..fc4. c01210ca `CMPLT B3,B0,B0` compares count with 64; >=64 returns ffff8a59 with B1=0 (c01210d8..10e4). <64 sets B1=1 and returns ffff8a65 (c01210d0..10d4). c01210ec skips the FIFO-copy loop for zero bytes. FIFO bytes otherwise use c0121116 `STB B0,*B5[B4]`, with B5=01e00000+(index&3), B4=0x420.
CSR0=01e00502 is read at c0121138; c0121142 shifts boolean B1 by 3; c0121146 ORs it into CSR0; c0121148 `SET B0,1,1,B0`; c012114a `STH B0,*A4[0]`. Thus full packets OR in 0x02 (TXPKTRDY); the zero/short final packet ORs 0x0a (TXPKTRDY bit 1 + DATAEND bit 3), preserving other read bits. c0121154..1156 then stores EP0 state 2. This is an explicit ZLP path, not a claimed hardware-generated ZLP from DATAEND on a full packet. Static evidence rules out a simply missing ZLP in this stock path; it does not establish timing or diagnose the root-port Code 10.
### A1 finding 3: interrupt continuation and enumeration scope (confirmed / limits)
Confirmed continuation: c0121c08 `MVK 6,A0`; c0121c0a `STW A0,*A4[0]`; c0121c0c `MVK 128,B1`; c0121c0e `STW B1,*B4[0]`. This produces event 6 for EP0 IN, whose c01807a0 dispatch entry is c015b2b4, closing the ZLP loop described above.
Confirmed unsupported descriptor-type behavior: c0134fac `SHRU A0,8,A1` extracts type; c0134fc0 `SUB A0,1,A0`; c0134fc4 `CMPLTU 6,A0,A0`; c0134fc8 branches to c0135368 for types outside 1..7, including BOS (15). c0135368 sets error ffff8acc; the common request failure path c0135ab8 calls c0120ef8 with A4=128/B4=1 (STALL). This is not evidence that the STALL causes Code 10. GET_STATUS is separately dispatched (c0180210 word 0=c01354f8), not automatically treated as unknown. Device qualifier (type 6) reaches a supported dispatch slot; actual availability and string 0xEE were not resolved here. No measured latency or root-port-specific timing conclusion is possible from this static audit.
Hardware interpretation: [TI SPRUFM9H](https://www.ti.com/lit/ug/sprufm9h/sprufm9h.pdf), peripheral control transfer and PERI_CSR0 sections, describes DATAEND as the data-stage end indication and TXPKTRDY as packet availability. Setting DATAEND on a full packet alone must not be described as changing its wire payload into a short packet; this firmware explicitly queues zero bytes when required instead.
### A2 finding 1: final buffer producer and mute gain (confirmed)
The tap is downstream of the final integer filter/mute stage 118186e0 and the float-to-integer stage 11818428, upstream of the fixed packer gain. 11818798/118187a8 construct 11f038b0; 118187b4 `STW B4,*B9++[1]` writes planar output. The two-channel loop continues at 118187b8..11818810. c012-independent audio order is 11818c5c -> 11818428, 11818c60 -> 118186e0, 11818c64 -> 11818aa0 (call addresses verified in the final pass).
118186e0 reads 11f03ebc (A6=11f03eb4 plus 8, c11818760/1181876c [address prefix correction: 11818760/1181876c]); its delayed value reaches the final `SMPY32 B17,B4,B4` at 118187a0 before the output store. This is a mute/ramp coefficient, not yet a proven master knob: c016d200 passes target 0x7fffffff and ramp 221 to c0164684 with A4=11f03ebc; c016d220 passes target 0 and ramp 397 to the same helper. Thus those digital fades affect USB. These binary targets must not be mistaken for proof of the variable master-volume control.
