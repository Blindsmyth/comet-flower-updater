Zoom G1 / G1X Four — DSP Firmware Architecture & Technical Roadmap

Technical teardown, on-chip L2 cache patch, and hardware controller architecture for the Texas Instruments TMS320C6745 DSP.
Status: Patch Built (res1_patched.bin) Architecture: TI C674x VLIW DSP (300 MHz) Branch: recon/audio-cache-patch

1. The Bottleneck Discovered

Profiling on physical hardware revealed that 19% to 25% of audio processing time is lost to CPU memory stalls. The effect code runs from external SDRAM, causing cold cache misses on every 16-sample audio block.

2. The Silicon Patch Applied

We reconfigured the DSP's internal cache controller from 128 KiB to 64 KiB, freeing 64 KiB of fast on-chip L2 SRAM. Slot 0 was relocated to this SRAM, completely removing SDRAM instruction stalls for the lead effect.

3. Dual-Purpose Controller Plan

Reverse-engineered the pedal's integrated USB core, front-panel buttons, footswitches, and quadrature rotary knobs. Blueprint designed to add a power-up gesture to operate as a standard USB MIDI controller.

1. Memory Architecture: Stock vs. Patched

Hardware L2 Partitioning
In Plain Terms: The DSP chip has 256 KiB of high-speed memory right on the chip die. In the factory firmware, half of it was set aside as a general cache, forcing sound effects to load from a slow external memory chip. Our patch claims 64 KiB of that on-chip memory specifically for Slot 0, so the primary amplifier/distortion model never waits on external memory.

Why only Slot 0? Each effect slot requires 40 KiB (0xA000). Fitting all 5 slots would require 200 KiB. With ~138 KiB already required for the Zoom RTOS/stack and 64 KiB retained as cache for the rest of the system, exactly 64 KiB of free SRAM is available. This accommodates one complete slot (Slot 0) with 24 KiB left over.

2. Audio Pipeline & Patch Execution

44.1 kHz Real-Time Flow

The c016e380 Discovery: The stock loader wrote back L2 cache after loading a module, but never invalidated the L1P instruction cache. We found that c016e380 occupies an isolated 32-byte fetch packet, allowing us to replace it with 8 sequential instructions that trigger an L1P flush and perform a tail call to the L2 writeback worker.

3. Hardware Controls & USB MIDI Mode

Reverse Engineering Teardown
In Plain Terms: The pedal's USB connection is wired directly to the DSP processor (not an external converter chip) and natively supports high-speed MIDI. We mapped every physical button, footswitch, and knob on the board so they can be routed to send standard MIDI messages to audio software (DAWs and amp simulators).

4. Exact Patch Machine Code (Audited & Verified)

Byte-for-byte disassembly of patched regions 
; 1. Early L2CFG Initializer at c016d08c (File Offset 0x61008 in res1_493412.bin)
; Replaces: f6 62 3c 00 (32-bit STW.D2T2 B0, *+B15[3])
; With compact 16-bit instructions:
4427          MVK.L2        2, B0              ; Set L2 mode = 2 (64 KiB cache) while L1D remains 3
fc05          STW.D2T2      B0, *B15[3]        ; Write L2 mode to stack structure

; 2. .fphead VLIW Fetch Packet Header at c016d09c (File Offset 0x61018 in res1_493412.bin)
; Replaces: 00 00 d0 e0 (0xe0d00000: mask 0000110b -> slots 1, 2 compact)
; With:     00 00 d0 e1 (0xe1d00000: mask 0001110b -> slots 1, 2, 3 compact)
; Declares compact instruction pairing for slot 3 so CPU does not trap on boot.

; 3. Late L2CFG Table at c0181728 (File Offset 0x756b0 in res1_493412.bin)
; Replaces: 03 00 00 00 -> 02 00 00 00 (64 KiB L2 Cache Mode)

; 4. Active Slot 0 Base Table in .cinit RLE stream (File Offset 0x77efd in res1_493412.bin)
; Replaces: 40 1f c0 -> 00 82 11 (within stream 1a 05 00 ...)
; Decompresses to: 0x11820000 at c01839a8 with zero stream shift.
