How we know

Every claim carries its evidence

AI helpers write most of the first drafts. That's why no draft counts as fact until it has been reviewed, measured, or played on the pedal. Here's the process.

So far, review has found 1–2 wrong "confirmed" details in every chunk: offsets that ignore index scaling, callees nobody read, two tables treated as one, misnamed dispatchers, a mistyped address. That rate is the reason the review step is required.

confirmedRead in the code

Instruction-level evidence: a register write, a string reference, a known chip register, or the pedal measuring it.

likelyStrong pattern

Call graph, data flow and naming all agree, but nobody has traced the code line by line.

guessPlaceholder

A working name so the map can be read. Labelled as a guess, and never used as the basis of a firmware change.

hardwarePedal is the judge

A static estimate isn't trusted until the pedal agrees. DR103 was estimated at 50–70k cycles and measured at 227k.

Measured on the pedal

The DSP's cycle budget per audio block

A diagnostic effect burns a known number of cycles. We raise it until the pedal freezes, which happens at about 96–102k cycles per block. Effect timings come from the C6745's own cycle counter and are reported as an audible tone.

"Kernel" = the effect's own DSP code, timed with a cold cache. "In a patch" = the load-test cost, which adds about 7k outside the kernel (accurate only to about ±6–10k). Five effects at 17k each fit the budget, but five at 24k don't. That's why the cache-refill overhead matters, and the Slot 0 L2 patch targets it. CF Muff shows a static estimate only; it hasn't been played yet.

Built, waiting for the pedal

Three firmware changes, tested in a set order

USB MIDI controller mode

test first

Hold the Rhythm/Looper button at power-on, and the knobs, switches and expression pedal send MIDI CCs over USB. Normal power-on must behave exactly like stock.

  • Code sits in free SDRAM at c01a0000, with 4 hooks
  • MIDI is sent without blocking (recon/19)
  • Test updater SHA-256 c6317cac…; steps in recon/04
  • Boot and recovery regions untouched; Zoom's v2.00 updater restores it

Slot 0 L2 residency patch

second

Keeps the first slot's code in fast on-chip memory, so it doesn't refill from SDRAM every block.

  • Static checks closed (recon/16 C11/C12)
  • Cache-safe per TI's SPRUG82A
  • Needs a heavy effect to show a measurable gain

USB audio

after controller passes

The pedal as a USB audio interface. A prototype that streams silence is designed and compiled.

  • Design: recon/17, 18 (item 3), 20
  • Prototype: firmware/usb_audio_proto/
  • Only wired in once controller mode passes on the pedal

What's left

The remaining work, in order

  1. Finish chunks 09, 10, 11 next

    240 functions. Resume 09 after c0142420, 10 after c01489a0, 11 after c014a0cc.

  2. Map chunk 07

    150 functions, c0136674..c013b1f4. The Codex run hung waiting on stdin; rerun it with < /dev/null.

  3. Map chunks 12–18

    About 970 functions, c014d124..c016ec40. The biggest remaining piece.

  4. Map the boot/update program

    Resource 5 (build/codex7/boot.dis), using the same table and review process.

  5. Write docs/FIRMWARE_MAP.md

    The readable overview: the firmware's structure by task and subsystem, built from the chunk tables.

  6. Pedal tests when the owner is back

    Controller mode, then the Slot 0 L2 patch, then USB audio. Also play CF Muff and CF RAT against Zoom's own models.

  7. Fill the 5 slots

    More effects ported from the JUCE source, each at the lowest cost that sounds the same, until a full 5-slot patch fits the budget.

  8. Package the patch tool

    Owners apply our changes to their own copy of the firmware. We don't redistribute Zoom binaries.
