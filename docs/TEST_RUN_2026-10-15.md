# Owner test run 2026-10-15: controller mode + diag readout on the pedal screen

Kit: `build/test_kit_2026-10-15/` (built from commit HEAD of this doc).

| File | SHA-256 (start) | What |
|---|---|---|
| `TEST_G1X_diag_ui_updater.exe` | `e6c047405b5b31a9` | Stock v2.00 + controller mode + USB diag + on-screen diag readout |
| `RESTORE_stock_fw_factory_fs.exe` | `38c6b74d6877b5aa` | Back to stock firmware + Zoom's factory effects |
| `res1_diag_ui.bin` | `3ab104ee706b994a` | The firmware inside the TEST updater |

Both updaters write **only** main firmware (`0x033000`) and the effect file system
(`0x102000`); the boot/update program and the settings sector are never written
(`check_updater_stages.py`: all ok). Update mode lives in the boot program and is
decided before main firmware runs (recon/25), so a bad main firmware is always
recoverable with RESTORE.

**Note:** both updaters put Zoom's factory effects back. CF effects need to be
reinstalled afterwards with CF Loader.

## 0. Before you start
- Close ToneLib, Zoom Guitar Lab and any MIDI tool that might hold the pedal's port.
- The USB port is a hand-soldered repair (recon/07). If a transfer stalls, **do not power-cycle**.
  Re-plug USB only and re-run the updater.

## 1. Flash the TEST firmware
1. Unplug USB. Hold **both footswitches**, plug USB in, keep holding until **FIRMWARE UPDATE** shows.
2. Run `TEST_G1X_diag_ui_updater.exe`. Select MIDI IN/OUT = **ZOOM G Series**, then click **Execute**.
3. Wait for **Version update completed**. Then unplug.

## 2. Normal boot (stock behaviour expected)
Plug in **without** holding anything.
- Expected: the pedal boots and behaves exactly like stock. The screen is the normal patch
  screen, and there is no diag text: the UI draws only in controller mode.
- Report: whether it booted, and anything odd.

## 3. Controller-mode boot (the real test)
Unplug. Hold the **Rhythm** button (GPIO0), plug USB in, release after the logo.
- Expected screen, within about a second (5x7 text, 4 lines):
  ```
  DIAG W#1 t<ticks counting up>
  STACK <n>/2048
  USB OK q0 F0x0 TD0
  sent 0  q 0
  ```
- **Tick period:** read `t` twice, about 60 s apart by a stopwatch, and tell me both numbers.
  This measures the SYS/BIOS tick, which is still unproven.
- Turn knobs, press buttons and footswitches, and move the expression pedal: `sent` should climb
  and the last line should show `CC<n>=<value>`.
- Optional, on the PC: `.venv/Scripts/python.exe tools/cf_midi_monitor.py` should show the CCs.

## 4. Readback over MIDI
1. Close the monitor. Run
   `.venv/Scripts/python.exe tools/capture_ctl_diag.py --port ZOOM --out build/diag_capture.json`.
2. Press **both footswitches together**. The capture tool prints the decoded report.

## 5. Reconnect (only with batteries or the AC adapter in)
On USB power alone, unplugging powers the pedal off, so skip this step.
With batteries or the adapter: unplug USB and re-plug it. Expect `NO USB` while it is
unplugged, then `USB OK` and `W#2`; the stack mark starts fresh. Repeat step 4.

## What to send back
A phone photo of the screen in step 3, the two `t` readings with the stopwatch gap, the
`STACK` value after you exercise the controls, and the capture output from step 4.

## Abort and recovery
- Stuck at the logo, a garbled or frozen screen, or no USB: unplug. Hold both footswitches,
  plug in, and run `RESTORE_stock_fw_factory_fs.exe`, the same as in step 1.
- If the screen shows `TX STALL` (the known liveness risk), note it, then re-plug USB.
  That is a finding, not a failure of the test.
