## The direction (owner, 2026-10-18)
Design CF effects **for the C6745 itself**, not port-then-squeeze; C with compiler control, hand asm only where a
loop clearly falls short. Target: **CF Master**, one effect over all 5 slots running more than 5 effects inside
(the 1979 *Comfortably Numb* rig). Guide and lessons: **`docs/C6745_DESIGN.md`** (§1 chip, §2 baseline, §3
rules, §3b-3g per effect). Every `tools/build_g1.sh` now writes `build/<FILE>.LOOPS.md`
(`tools/c6x_loop_report.py`: ii, feedback bound vs unit bound, why a loop is not pipelined).

Key findings:
- Feedback chains, not units, set the cost (4-cycle latency per dependent float op). Every CF sample loop was
  unpipelined or feedback-bound; Zoom's drives run at ii 10-14.
- State behind a pointer became a memory chain (Muff: dep 116); scalar locals fix it. `cond ? f() : x` and
  `cond ? buf[i] : 0` became branches / predicated loads; compute first, then select. `restrict` on the bus.
- Delays longer than the block decouple feedback inside a block (Mistress, CE-2, Delay): reads, then work,
  then writes.
- CF Watt's NFB loop (~8.2k/block) is serial by design; in CF Master the independent RA-200 path can run in
  its idle units.
